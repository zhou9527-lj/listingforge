# 本地数据与工程包

## 数据目录

- 应用数据库：系统 AppData 下的 `listingforge.db`。
- 项目目录：用户选择位置，包含 `project.json`、`assets/`、`results/`、`canvas/`、`exports/` 和 `logs/`。
- 缓存：系统 AppCache，可安全清理和重新生成。

## 核心表

- `projects`：项目标识、名称、路径、平台、类目、更新时间。
- `assets`：素材角色、文件路径、哈希、尺寸和 MIME。
- `product_profiles`：视觉理解结果和用户修订。
- `generation_plans`：平台、类型、提示词、候选数和费用预估。
- `tasks`：供应商任务 ID、状态、重试、费用、错误与时间戳。
- `results`：结果 URL、本地路径、过期时间、质量评估和选择状态。
- `canvas_documents`：页面、图层 JSON、尺寸和版本。
- `exports`：格式、目标路径、校验和与完成时间。
- `settings`：不含秘密的本地偏好。
- `global_assets`：应用级跨项目素材及其分类、文件路径、哈希和元数据。
- `custom_generation_types`：用户自定义图片类型、比例、候选数、提示要求与全局参考图关联。
- `agent_conversations`、`agent_messages`：按项目隔离的 Agent 会话和消息历史。

当前迁移版本为 v5；启动时开启 SQLite 外键约束。全局素材存储在应用数据目录，复制进项目后才参与项目生成，删除全局条目不会破坏已经复制到项目的文件。

- v4：`assets` 增加 `idx_assets_project` 索引（项目页列表查询路径优化）。
- v5：`results` 增加 `idx_results_task` 索引；`saveDownloadedResult` 幂等（先删同任务旧行再插入），`loadPersistedResults` 按任务取最新一行去重，修复"4 张唯一图片显示成 48 行重复"。

删除语义（记录 + 文件同步删除）：结果图片与任务行均可单独删除，删除任务时 `results` 由外键 `ON DELETE CASCADE` 级联清理；本地文件删除由 Rust 命令 `delete_project_result_file` 执行，仅允许删除当前项目 `results/` 目录内的文件（规范化路径校验后执行）。`assets` 新增 `canvas` 角色（画布导入图片素材）。

## 工程包

`.listingforge` 是 ZIP 容器，包含清单、画布 JSON 和可选择的素材/结果。导出前验证路径和文件大小；导入时拒绝绝对路径、`..` 路径穿越和重复清单。API Key、系统凭据和全局日志永不进入工程包。

## 迁移

清单包含 `schemaVersion`。每次升级先备份原清单，再按顺序执行迁移；失败时保留原文件并给出可复制诊断信息。
